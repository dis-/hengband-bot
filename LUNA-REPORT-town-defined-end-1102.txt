LUNA-REPORT town-defined-end-1102（町の決まった終わり方・構造の直し第2段B と一緒に）

== 持ち主の決定 ==
2026-11-02 「決まった終わり方だけにする」: 町で担当が全員答えない時は (1) 出発の条件を満たしていれば出発、
(2) 満たせない条件が生存に関わらなければそれを諦めて出発、(3) 生存に関わる条件が満たせなければ名前を付けて止める。
歩き回る抜け出しは町では使わない。

== 設計 ==
- 町の終わり方は town_terminal.py の「town end」の節だけで決める（gather_town_end / verdict_town_end / town_end_key）。
  新しい仕組みは足さず、既存の force_visit_departure（10-14 A0 の強制出発）と _town_blocked_key（名前付きの止まり）に渡す。
- 入口: 本当の町のマス（snapshot.in_town。荒野の移動中は含まない）で、ダンジョン用の最後の手段
  （往復時の breakout:least-visited、何もない時の _town_idle_key の stuck:wander）に落ちた時だけ。
  そこに来るのは、生存（戦う・逃げる・休む・食べる）と町の担当がすべて答えなかった時（_decide の順番はそのまま）。
- town_end_key の順:
  1. 店回りの進め（_town_procurement_progress_key）に進む一歩があればそれ（今まで進捗の継ぎ目が stuck:wander を
     書き換えていた一歩。判定は同じ _town_result_makes_progress）。
  2. 採掘で入口の無い町なら町0へ戻る（2026-09-24 の決定。継ぎ目から _mining_walk_in_return_key へそのまま移した）。
  3. 店の入口のマスにいれば、既存の安全な一歩で入口から降りる（担当は入口の外で自宅の取り出しや道を組むため）。
  4. 町の地図のクエスト報酬が町を押さえている間（town_quest_reward.holds_town）は出発させず、答える担当が無ければ
     town:blocked:quest-reward-first で止める。
  5. 判定: 出発の最低条件（_departure_minimum）が全部満たされていれば、満たせない普通の出発条件を名前で諦めて
     force_visit_departure(cause=no-owner-answered) で出発（帰還を読むか歩いて入るかは今までの出発と同じ）。
     諦めた条件は keep-running-events.jsonl の closed_work.dropped_conditions に残る。
     最低条件のどれかが満たせなければ town:blocked:survival:<最初の項目> で止める（最終停止の接頭辞として登録）。
     同じ訪問で一度強制して失った出発は二度強制せず、既存の departure-unsatisfiable で止める（10-31 の決まり）。
- 町では breakout:least-visited・boxed breakout travel・stuck:wander を使わない。ダンジョンでは今のまま。
  boxed breakout の書き換え（3つの関数・継ぎ目の分岐・claim の型2行・lint の例外・purity の検査のマス）は消した。

== 4つの再起動の種類 ==
- loop-detected（28）: 町で担当が答えない時の breakout／boxed travel／stuck:wander の1秒ごとの往復（D61、n1-c 11-01 23:50）は
  起きなくなる。進める一歩が無ければ (2) で出発するか (3) で名前付きで止まる。ほかの根（店や自宅の中の往復）は各担当のまま。
- departure-unsatisfiable（23）: 今までも force_visit_departure を通っていた（最低条件を満たせば (2) で出発）。
  再起動になっていたのは最低条件が満たせない時（例 n1-b life-282・n1-a life-464 02:06 は identify_staff_ready）＝(3)。
  名前は既存の departure-unsatisfiable のまま（記録の minimum.failed に項目がある）。
- owner-retired-burst（18）: 同じく force_visit_departure を通る。n1-b life-283 23:34 は最低条件
  （recall_departure_ready・food・cure・teleport）が満たせず (3)。名前は既存のまま。
- pack-full-no-room（4）: 出発用の買い物が荷物の空きだけで断られる既存の名前付きの止まり。変えていない。
- 追加の証拠: n1-a life-464 02:04 overweight-home-full-no-legal-relief は既存の名前付きの止まり（重さは最低条件）＝(3)。
  n1-c life-100 02:04 equipment-transaction:home-route-repeat-terminal は装備の取引の止まりで、町の終わり方の外（D34 の系統）。
