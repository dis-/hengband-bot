# Maintainability review 2026-11-09 step 8 (owner 2026-11-13 「ログの圧縮を別で行うことで
# botを止めないことと容量節約を両立できないか？」): the bots keep writing pickles; this turns

[Unit]
Description=Convert recorded Hengband bot policy pickles to json_snapshot

[Service]
Type=oneshot
WorkingDirectory=%h/hengbot-smoke/bot-current
Environment=PYTHONPATH=%h/hengbot-smoke/bot-current/src
ExecStart=/bin/sh -c 'exec %h/hengbot-smoke/venv/bin/python -m hengbot.json_snapshot --min-age 172800 %h/hengbot-soak/n1-*/life-*/incident-captures'
IOSchedulingClass=idle
MemoryMax=4G
TimeoutStartSec=3h
# 1: some pickle could not be read (a class removed since it was written); it is kept and named
# in the log, the rest is converted.
SuccessExitStatus=1
StandardOutput=append:%h/hengbot-soak/json-snapshot.log
StandardError=append:%h/hengbot-soak/json-snapshot.log

--- hengbot-json-snapshot.timer ---
[Unit]
Description=Convert recorded Hengband bot policy pickles every hour

[Timer]
OnBootSec=20min
OnUnitActiveSec=1h

[Install]
WantedBy=timers.target

  systemctl --user daemon-reload && systemctl --user enable --now hengbot-json-snapshot.timer

決めた値の理由と注意:
- 対象は各 life の incident-captures だけ。生きているボットの jsonlog/town-arrival（3 回分で回る）は
  触れない。そこから capture へハードリンクされた pickle は、jsonlog 側のリンクが回って消えるまで
  場所を取るが、capture 側は 1 回の変換で JSON になる。
- --min-age 172800（48 時間）: tests/extract_*.py の 54 本が capture の
  town-arrival/<visit>/policy.pkl を名前で読む。止まりを直すために写して固定を作るのは
  たいてい当日なので、新しい capture は pickle のまま残す。48 時間より古い capture から固定を
  作る時は、extract の読みを town_arrival_checkpoint.policy_file に替える必要がある
  （restore_checkpoint_bytes と replay_town_arrival は両方の形を読む）。
- 変換しない物: incident-*.json.gz の中に base64 で埋めた checkpoint（latch_onset_capture）。
  *.pkl のファイルだけが対象。
- 古い life の pickle が今のコードの型で読めない時は、その pickle を残して log に書き、
  残りは続ける（exit 1。上の SuccessExitStatus で unit は失敗にしない）。
- 見込み: テストの 114 本では pickle 2,561 MB → 103 MB（約 4%）。ボットの書き込みの速さは
  不変（30cefa0678 の測定）。
- n1-c の instance が bot_budget_n1.py の INSTANCES に無いのは手元の写し（10-31）の話で、
  サーバの版は確かめていない。上の glob は n1-* なので 3 体とも対象になる。
