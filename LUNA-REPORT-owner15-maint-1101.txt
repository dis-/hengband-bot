■ 15. 付け替えの道具 scripts/town_work_rekey.py
  使い方: PYTHONPATH=src python scripts/town_work_rekey.py [--base REV] [--write]
  - 移動前の木を git の版から読む（既定 HEAD＝まだコミットしていない移動。コミット済みなら --base main など）。
  - review にあって今は選ばれない（stale）キーのうち、その関数が --base にあり作業ツリーから消えたものを、
    --base に無く作業ツリーに現れた、review の無い選ばれた関数と本体で突き合わせる。
  - 本体＝名前・docstring・位置を除いた AST（ast.dump、引数・飾り・注釈・中身は含む）。完全に同じ時だけ。
  - 1 対 1 の時だけ付け替える。同じ本体が 2 つ以上なら「手で」と表示、本体が変わったものは stale のまま表示。
  - 既定は表示だけ。--write は review の順番と中身（evidence などの文言）を変えずにキーだけ替えて書く
    （json.dumps(ensure_ascii=False, indent=2)、LF。基点の書式と同じ）。そのあと manifest --write で索引を作り直す。
  - 終了コード: 残り（手で直すもの）があれば 1、無ければ 0。
  - town_work_manifest.generate のエラー: stale がある時だけ
    「; if a function was moved or renamed, scripts/town_work_rekey.py re-keys its review (dry run, then --write)」を足す。
  - git から木を読む処理は town_work_manifest.revision_sources() にまとめ、town_work_churn.py もそれを使う
    （同じ 3 行が 2 か所にならないように。churn は ROOT を一時ディレクトリに替えるので git は lint.ROOT で動かす）。
  手で確かめた流れ: 作業ツリーで _town_destroy_key を _town_destroy_item_key に改名 → manifest が
  「unmapped=[…_town_destroy_item_key]; stale=[…_town_destroy_key]; …town_work_rekey.py…」で止まる →
  rekey --write で 1 件付け替え（review の差分は 1 行）→ manifest --write が zero unmapped。そのあと元に戻した。
  試験 tests.test_town_work_rekey（8 件、約 75 秒）:
  - RekeyPlanTest（合成）: 関数の移動（docstring を消しても）が付け替わる、メソッドの改名（docstring が違っても）が
    付け替わる、本体を変えたものは付け替わらない、同じ本体が 2 つなら手で、--write の順番と中身。
  - RepositoryRekeyTest（実際のリポジトリ）: TownMixin._town_destroy_key の改名、policy_home.py の HomeMixin への
    移動が付け替わり、作り直した索引が基点の索引のキーを替えただけと完全に一致。本体を 1 行変えた移動は付け替わらない。
    manifest のエラーが道具を案内することも確かめる。
  元に戻して確かめた（scripts を一時的に戻して実行し、戻した）:
