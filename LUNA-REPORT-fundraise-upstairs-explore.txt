---------

With those stacks removed as a DECLARED CONSTRUCTED variant, the base returns key `5`, reason `fundraise:upstairs-not-found`, despite 315 open frontiers. This discrepancy is recorded in `LUNA-DIAG-fundraise-upstairs-explore.txt` and the replay test.

`policy.py:11388` places `_fundraising_key#1` in the active ladder. `_fundraising_key` delegates an active return-to-town run to `_leave_fundraising_floor` (`policy_fundraising.py:1152-1165`). Before the fix, when the upstairs search had expired and `allow_recall` was true, the exploration and fallback ladder was an `else` of the expiry condition. If no readable Recall was found, that whole ladder was skipped and the code reached the terminal WAIT. Issue #47's ordinary exploration step is in the separate return owner at `policy_town.py:7489-7496`; fundraising exits do not invoke that method.

Change
------

`policy_fundraising.py` now finds a Recall scroll only for an expired search where Recall is allowed, then returns with the existing Recall action if the scroll is readable. Otherwise it reaches the existing `_explore_step` call, `_step_toward`, and fundraising route offer. That is the same exploration producer and movement/safety path used by issue #47. A known reachable upstairs route is still handled earlier. No HP, exploration, or search thresholds changed; no new policy attributes, helper, or reason were added. No restored-checkpoint defaults or `STUCK_FAMILY_REASONS` changes were needed.

The item sink adapter entry was updated to record the exploration call under the readable-Recall guard. `town_work_manifest.py --write` refreshed `town_work_manifest.json.gz` and `town_work_sites.json` (826 candidates, 20,904 sites, zero unmapped). No town producer baseline, town work review helper entry, or fixed structural census count needed changing. Three tests were added in `test_fundraise_upstairs_explore_recorded.py`; existing tests and assertions were not edited.
