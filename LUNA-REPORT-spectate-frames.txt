実装
--spectate-file PATH を指定すると、PATH と同じディレクトリの spectate-frames.jsonl に、投稿した通常の判断ごとに1行を追記する。UTF-8、LF区切りのJSONLで、従来の観戦JSONと同じ time、decision_sequence、key、reason、色付きscreen、HP・階層・装備・持ち物・敵・能力等の表示情報に、整数の frame を追加する。画面と表示情報は送信前に採取し、投稿を確認してからフレームを確定する。キー受付後に死亡やexecutor停止となった行動も、受理済みsegmentを確認して記録する。
frame は1から単調増加し、再起動時は既存ファイル末尾の完全な行から番号を再開する。再選択前の投稿拒否、抑制された投稿、マクロ内部の継続入力、プロンプト回答、回復用キーはフレームを増やさない。キーなしの判断は従来の観戦JSONの更新だけを行う。
spectate.json は原子的な置換と0.25秒間隔の制限を維持する。フレーム列にはこの制限を適用せず、投稿対象の判断ごとに attrs=True のscreenを要求する。画面取得に失敗した場合は既存のexecutor画面へ退避し、エラーは外へ送出しない。互換JSONとフレーム列の書き込み失敗は独立して扱う。

容量制限
上限は16 MiB（16,777,216バイト）。次の追記で上限を超える場合、最新の完全な行と今回の行を合わせて概ね8 MiB以下に縮め、一時ファイルから原子的に置換する。今回の1行だけで8 MiBを超える場合はその行を残し、16 MiBを超える単独行は保存しない。
置換できない場合は今回のフレームを捨て、上限を超えて追記を続けない。書き込み途中の最終行は次の追記前に修復する。ファイルI/Oの例外は捕捉し、stderrへの通知は従来と同じ最大1時間に1回とする。
読み手はファイルの置換を検出して開き直し、frame番号で既読行を除外する。サーバの実装や公開botの設定は変更していない。連携仕様は docs/spectator-frames.md に記載した。

バックログ制御
--spectate-max-backlog N を追加。既定値0は無効で、spectate-played.jsonを一切読まない。--spectate-fileがない場合も待機しない。
N > 0 では、通常送信・投稿拒否後の再選択の両経路で、送信前に同じディレクトリの spectate-played.json を読む。形式は {"frame": 最終再生番号, "time": Unix秒}。
最後に保存したframe番号と再生番号の差が N 以上なら、0.05秒間隔で確認し、N未満になるまで待つ。今回の判断のフレームは、この判定にはまだ含まれない。N=20なら0.25秒再生で約5秒分。一定間隔の再生はサーバ側が担当し、botが待つのは上限に達した場合だけである。
通知が存在しない、読めない、JSON・値が不正、10秒を超えて古い場合は待たない。負の番号、保存済み番号を超える番号、非有限値・未来の時刻も無効として待機を解除する。ちょうど10秒前の通知は有効とする。待機中にサーバの通知が古くなった場合も解除する。
既存の --min-action-seconds は維持し、同時指定にも対応する。観戦用botが固定間隔を使わなくなる運用変更は、この作業では行っていない。

時間管理
待機はchoose_keyの後、送信と応答期限作成の前に行う。判断watchdogを待機中は解除し、終了時に再設定する。
decision_started_at、phase_started_at、last_activityを実際の待機時間だけ補正し、choose_key_ms、send_ms、total_msに意図的な待機を混ぜず、無通信回復や停止判定も誘発させない。応答deadlineは待機と画面取得の後に作成する。
src/hengbot/cli.py のpost_decisionを通常・再選択の双方で使用する。spectator.pyの既存の近接攻撃表示・stale判定の式は変更していない。
