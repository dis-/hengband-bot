  選び方の規則（帯・同点の崩し方・入れ替えの条件）は変えていない。新しい規則・閾値は無い。

  既存の決まり。使うかどうかは所有者への問い（最後に書く）。

原因（詳しくは LUNA-DIAG-equip-tie-loop.txt）
- src/hengbot/warrior_equipment_evaluator.py:348-364（b6d47db93）warrior_melee_signature のキーは
  品物の id（見た目の識別。熟練度を含まない）だけだった。
- src/hengbot/warrior_loadout_evaluator.py:228-254 がこのキーで近接の結果を保持し、
  src/hengbot/warrior_optimization.py:551-571 WarriorEvaluatorCache がレベルなどの文脈が同じ間、
  判断をまたいで使い回す。
- カットラスの熟練度は 3192 -> 3992 に上がった（命中の項 trunc((熟練度-4000)/200) が -4 -> 0）。
  持ち物・装備中の id には 3192 の時の値（命中 4、1ターン 4.088）が残り、自宅の id は新しい値
  （命中 8、5.471）で評価された。ショート・ソードはどこでも 命中 6、4.163。
  このため毎回「自宅にある方」が上に見えて、入れ替えが往復した。
- 証拠: viewing server の loadout-report.jsonl（07:38:43 の報告 82 で pack のカットラスが命中 4、
  ループ中は同じ報告の中で home のカットラス 8 と equipped のカットラス 4）、
  bot-decisions.jsonl 4993/4994（ショート・ソードへ）と 5001/5002（カットラスへ）。
- 記録の盤面を新しい方針で通すと入れ替えない。熟練度 3192 で温めたキャッシュを持たせると
  記録どおりショート・ソードを取りに行く。これで原因を確かめた。

直し方（コミット f024865a1）
- warrior_melee_signature のキーの末尾に主手・副手の武器の熟練度を足した（11 行）。
  関数の約束（近接の評価が読む入力をすべて含む）どおりにしただけ。
  検索の重複除去のキーと、完了した検索の記憶はすでに熟練度を含んでいた。抜けていたのはここだけ。
- 末尾に足したので、warrior_loadout_search.py の _gear_state が使う 3〜10 番目の要素は変わらない。

戦士でも起きるか
- 起きうる。評価器とキャッシュは EQUIPMENT_CLASS_PROFILES の 0（戦士）と 16（魔道具術師）で共通。
  条件は、レベルなどの文脈が変わらない間に武器の熟練度が 200 の段を越え、同じ武器が別の場所
  （自宅など）で新しく評価されること。魔道具術師は Lv1 からの新しいキャラで熟練度が速く上がるので
  出やすかった。今回の直しで両方とも直る。
- 観戦中の戦士の直近の報告（n1-a life-447 の 509 件、n1-b life-274〜276 の 2,388 件）に
  同じ品の組が違う命中で並ぶ例は無かった（報告は上位3候補だけなので弱い否定）。
