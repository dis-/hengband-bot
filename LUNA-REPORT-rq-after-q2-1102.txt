1. オーナーの指示

  「angband 6F, 12Fのランダムクエストに挑む順が早いので達成率が低い。Q2の後に回したい」（2026-11-02）

2. 作ったもの

  Q2（下水道）が未受諾または受諾中の間は、鉄獄のまだ済んでいない一番浅いランダムクエストの階へ
  階段で降りない。潜るのはその1つ上の階まで（今のデータでは鉄獄5階まで）。
  Q2 が済んだら（達成・報酬・完了・失敗のどれか）この制限はなくなり、ほかは何も変わらない。

  - 新しいモジュール src/hengbot/random_quest_hold.py
    - first_held_level(policy, snapshot, dungeon_id): いま制限している一番浅い階（なければ None）
    - crossing_held(policy, snapshot, dungeon_id, current, destination): current < 階 <= destination か
  - policy.py の _is_descent_target（降りる先の判定。descend・approach-descent・seek-downstairs・
    stuck:seek-stairs が全部これを通る）に1か所だけ足した。ダンジョンの中だけで効く。
  - 階の数（6・12）はコードに書いていない。クエストの知識（lib/edit/quests/040〜049_RandomQuest.jsonc の
    "type": "RANDOM"・"level"・"dungeon"）から求める。職業による分け方もない。

3. ゲーム本体の根拠

  - birth/game-play-initializer.cpp init_dungeon_quests: ランダムクエスト 10 件は生まれた時に全部 TAKEN、
    階はデータの level のまま（鉄獄 6・12・24・38・44・50・56・62・76・88 階）。
  - dungeon/quest.cpp leave_quest_check: ランダムクエストの階を出ると FAILED（ONCE と同じ扱い）。
  - QuestList::find_shallowest_random_quest_id（quest-list.cpp:523）と bot-json-output.cpp
    make_disclosed_quests_json: 進行中のランダムクエストは一番浅い1件だけ、しかも鉄獄の最深到達階が
    その階に届いてから開示される。済んだもの・失敗したものは開示される。未受諾の固定クエスト（Q2 の
    UNTAKEN）は一覧に出ない。
    → 「開示された行が済んだと言っていなければ未了」、「Q2 の行が無いか TAKEN なら Q2 は未了」とした。
  - spells-world.cpp recall_player / reset_recall と dungeon-processor.cpp:114: 帰還の深さは
    実際に立った最深の階か、それより浅く下げた階にしかならない（rumor.cpp:52 は最浅の階）。
    ランダムクエストの階に立って出れば失敗になるので、未了のランダムクエストの階より深い所へ
    帰還で着くことは起きない。そのため帰還先の選び方（_recall_destination_safe・
    _pick_alternate_dungeon）には手を入れていない。「この階に戻って来ますか？」の問いも浅くする
    向きだけなので影響しない。

4. 既にその階にいる場合

  制限は「今の階 < クエストの階 <= 行き先」の時だけ。ランダムクエストの階（やそれより深い所）に
  既にいる時は何も変えず、クエストの担当と出口の鍵（_quest_floor_exit_locked）に任せる。
  クエストを片付ければ次の未了の階（12階）までの制限に変わる。

5. 制限の階で降りられない時の動き

  新しい振る舞いは足していない。耐性が足りない時の深さの制限と同じく、その階を探索し、探索し終われば
  既存の「stuck:seek-stairs / stuck:ascend」で上り階段から新しい階へ行き、帰還の引き金（物資・光源・
  荷物など）がそろえば町へ帰る。生存処理は変えていない。
