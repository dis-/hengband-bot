   麻痺知らず（free_action）は無い（depth_safety の has に無い）。

   6695 1268303 HP219 (2,2)  'rd' emergency:teleport（狼3・チーターマン『アポロ』）
   6699 1268337 HP191 (2,43) 'rd' emergency:teleport（疫病人間・アリ）
   6700 1268346 HP193 (18,57) 're' return:recall
   6701-6715 1268357-1268495 HP194→212 '5' return:wait-recall（6715 でアイス・コボルドが距離2）
   6716 1268509 HP213 (18,57) '6' melee  ← 致命
        アイス・コボルド（race 1112）距離1、ランゴスタ（race 1252、速さ +10 = 120、
        攻撃 STING/CRUSH 効果 PARALYZE、lib/edit/MonraceDefinitions.jsonc id 1252）距離2。
   この後、ランゴスタは1回の行動の間に2回動ける（120 と 110 のエネルギー比 20:10）ので、隣に来て刺し、麻痺が続いて死亡。

   使わなかった理由（main 31306b6a8）:
   - 麻痺の敵の処理 _paralyzer_prevention_key（policy_combat.py:2606-2610）は「隣にいる」（distance <= 1）
     麻痺の敵しか見ない。距離2のランゴスタは対象外で、テレポートを読まない。
   - その下の状態異常の段（policy.py:11299-11311）は、別の敵と隣接して戦っている時、近づいてくるだけの
     麻痺の敵を外す（「Finish the fight already in contact」、2f8fecf53 08-17）。
   - そのため combat の melee（コボルドを殴る）になった。
   main で再現: 記録の 22 盤面（1268300-1268509）を新しい policy に渡し、22 判断すべてが記録と同じ
   （最後は '6' melee）。→ main は直っていない。

   根: 「隣にいるか」で麻痺の敵の接触を判定していたこと。速い敵は、こちらの次の行動の前に近づいて殴れる。
   ゲームの仕組み: 毎ゲームターン、プレイヤーも敵も speed_to_energy(速さ) ずつ溜まり
   （core/player-processor.cpp:133、monster/monster-processor.cpp:677）、1回の行動に ENERGY_NEED() =
   randnor(100,25)（core/speed-table.h:6）。こちらの1回の行動の間に敵は平均で エネルギー比 回動く。
   path 歩先の敵は path-1 歩と1回の攻撃が要る。
