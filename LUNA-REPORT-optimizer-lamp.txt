#86 REPORT - optimizer never chose the Home Feanorian lamp (branch optimizer-lamp-1019, base 3cb276a3)

DIAGNOSIS (measured; details with file:line in LUNA-DIAG-optimizer-lamp.txt)
- Cause: catalog dominance pruning, not scoring and not the Home visit limit.
  warrior_loadout_search.py _item_dominance_parts dropped the subtype (sval) for lights. The Home
  暗視の松明 (+1赤外線視力) (home:6e94dd272b55f172:0, pval 1) therefore "dominated" the Home
  フェアノールのランプ (home:ff2b3ffaa208a881:0, pval 0) and _prune_dominated_catalog removed the lamp
  before the search. Only the worn light is protected from the prune.
- (a) The lamp was in the catalogue (111025 ~9 row item 28; legal, evaluable, not incomplete) but
  never reached the search candidates.
- (b) Lamp, lantern and torch loadouts have identical LoadoutMetrics; at equal metrics the selection
  ranks permanent > lantern > torch (light_source_quality). Measured: lamp alone at Home -> lamp chosen;
  lamp + infravision torch at Home -> worn lantern kept. The comparison rule is sensible; the prune
  removed the lamp first.
- (c) 101730 decision 4644 (departure, turn 994876): best = worn lantern, transaction_actions 0,
  outstanding_equipment_work False, so home_visit_limit stayed 3 (it is 300 only while equipment
  work is outstanding, policy_town.py:4543); home_blocked True was a consequence. The bot departed
  with the lantern (3898 turns) and no oil (#82 oil waiver) and ran dry. 111025 (turn 1068217, worn
  0-turn torch): the recorded transaction 4767118d3bb15871 withdraws the +1 infravision torch, not
  the lamp. The #79 report's reading ("withdrawing that Home light") was the torch.
- (d) 10-03 is NOT the same mechanism: the worn lamp tied the Home ★ガラドリエルの玻璃瓶 / ★知識の石
  (LITE_3), because light_source_quality ranks every sval >= 2 as 2 (radius ignored) and the current
  set wins the tie. A radius-aware rank is a separate rule (owner decision on artifact light
  ordering). Not changed here.
- Side effect of the same key: disposable_dominated_item_ids on the 111025 catalogue listed the Home
  lamp and the pack lantern as disposable on 3cb276a3; after the fix only the 3 plain Home torches.

FIX (commit 056b3386; manifest 6e04af7f)
- src/hengbot/warrior_loadout_search.py _item_dominance_parts: keep the light subtype in the exact
  dominance part (as launchers already do): `signature[2] if launcher or light else None`.
  No new constant, threshold or policy attribute. Same-sval dominance (torch vs torch) unchanged.
- #82's oil rule is not duplicated.
