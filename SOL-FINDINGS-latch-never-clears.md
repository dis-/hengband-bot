# Why `_town_blocked_reason` never clears

All findings are **MEASURED** unless explicitly labelled **NOT ESTABLISHED**. I used `scratchpad/probe_latch_clear_sites.py` outside `tests/` to trace the seven assignments found by `rg -n '_town_blocked_reason\s*=\s*None' src/hengbot/policy.py`. The probe replayed the 26 retained snapshots at turns 2940731--2940986 through public `choose_key`, after restoring only the retained-slice boundary state documented by the accepted predecessor trace: floor `(0, 0, 0)`, already in town, calibration phase `deposit`, and latch `no-safe-recall-destination`. The replay was accepted because every decision reproduced key `5` and `last_reason == "town:blocked:no-safe-recall-destination"`; the latch had the same value before and after every decision. Any divergent replay would have been rejected.

## Answer

**MEASURED:** From the stalled state, the latch is terminal by construction. The only transition-based clears require a different town id (`policy.py:4952-4966`) or floor (`:5385-5517`). The five nominally in-town clears require a newly installed equipment transaction, an existing transaction to abandon, a failed pending Home withdrawal, or active fundraising/detection-stockout state. The accepted trace measured all of those owner states absent (`session=None`, `home_pending_item=None`, `fundraising_mode=None`), while the only live town claim was `deposit`. The already-latched owner returns key `5` and does not mutate any of those prerequisites. Across 26 varied retained surface snapshots, none of the seven assignments ran and none of their prerequisite states advanced. Therefore no clear site is dynamically reachable from this stalled state without first escaping the latched path; the only clear whose normal trigger directly changes location is the floor-change clear, and the emitted `5` cannot produce it.

**NOT ESTABLISHED:** The retained artifacts still do not establish which call installed `no-safe-recall-destination` at turn 2940690. That onset is not needed to establish why the already-latched state cannot release, but it is needed before selecting a defect repair. No repair option is offered because changing clear semantics without the missing onset path could mask a legitimate terminal condition or reopen an unsafe recall/departure loop.

To settle the onset before repair, capture from the last decision before turn 2940690 through the first two decisions after it, triggering when `_town_blocked_reason` changes from `None` to a non-`None` value. Each decision record must contain: turn, snapshot type/store context, floor/town id, position, emitted key and `last_reason`; `_town_blocked_reason` before and after; the assigning `file:line` and caller chain; `_calibration_phase` and calibration entry blocker; `_town_claims_active` plus claim categories; `_town_store_attempted`, visit-ledger blocked stores/approach failures; `_town_errand_plan` current stop; `_fundraising_mode`; `_equipment_transaction_session` phase/context; `_home_pending_item`; the recall destination candidates and the exact rejection predicate/value for each. It is conclusive only if a public-`choose_key` replay from the captured pre-decision policy checkpoint reproduces both the installing key/reason and the following latched key/reason exactly.
