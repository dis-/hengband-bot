## Changes

- F3(a): after an observed Identify-staff inscription and confirmed release
  sale, the in-store selector now chooses the required strictly fuller staff
  from the fresh page before unrelated work. The pure
  `_departure_blocking_page_operation` selector models a legal release sale
  followed by its fuller buy. A no-effect release sale or exhausted entry
  budget publishes the existing typed
  `town:blocked:shop-required-operation-uncomposable` terminal. An unconfirmed
  buy keeps the existing no-retry `shop:in-store-done` exit.
- F3(b): after sale-effect accounting, a whole Home-relief dispatch yields to
  the live, verified, same-entry page operation. Pending buy ownership stays
  with the in-store confirmation path. An exhausted operation budget retains
  the existing budget and publishes the typed terminal when the required
  operation remains.
- F3(c): charged Identify-staff Home relief takes are rejected only when
  readiness is false and carried count plus the entire requested quantity is
  at least four. Atomic dispatch revalidates this before posting. Empty
  Identify staves remain unrestricted surplus for sale or destruction; the
  no-fuller-stock destroy control is preserved. The skip fingerprint uses
  carried count/readiness and Home quantity changes, not price, gold, or turns.
- Added nine declared F3 boundary tests, including the constructed 014739
  reconciled board with `operation_posted=False`, the primary three-plus-one
  empty-staff case, and a separately constructed 184438 four-plus-two case.
  Added the required `import tests` session-package marker to the F2 and F3
  test modules; no F2 policy implementation was changed.
- Regenerated the town-work manifest: 815 candidates, 20,278 sites, zero
  unmapped. The reviewed pure selector and existing-terminal adapter are
  recorded in the town-work review/baseline. Ownership classification digest
  and final-stop registry were unchanged; F3 reuses the F2 terminal and CLI
  banner.

## Pins and predicate reversions

The nine F3 tests were copied into a scratch worktree at `1bb86903` and failed
there: 4 failures and 5 errors. The failures covered missing same-entry
buy-priority, missing pending-operation relief yield, the old budget terminal,
the empty-staff destroy candidate, and the three-plus-one empty take. The
errors covered the absent required-page-operation and Identify-cap helpers,
the absent yield/skip helpers, and missing required-operation diagnostics for
the constructed 014739 no-effect boundary. On the implementation, all nine
F3 pins pass.

Each new predicate was reverted independently and its pin failed again:

- Removing same-entry required-buy priority made the sale-continuation pin
  select row `k` instead of required row `o`.
- Disabling the relief-yield guard made the pending-buy whole-dispatch pin
  fail its yield assertion.
- Making the charged-cap predicate always false made the charged-cap rejection
  pin fail.
- Replacing the required-operation stop with the old leave path made the
  budget pin return `shop:in-store-done` instead of the typed terminal.
- Making `_departure_blocking_page_operation` return `None` made the
  release-sale-then-fuller-buy pin fail.

No existing test expectation was intentionally flipped. The initial broad
run exposed an invalid `.reason` access on `HomeErrandRequest`, a recursive
claims-producer call, and an overly broad no-effect stop. These were corrected
to use `.purpose`, yield until the next relief decision, and apply the F3
no-effect terminal only to a pending release sale. The recorded unconfirmed
buy no-retry control passes unchanged. The final broad run also caught the
session-package import requirement; the two test-only imports were added and
`test_runtime_file_isolation` passes.
